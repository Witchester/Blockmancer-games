# Blockmancer Dungeon — Master Game Design Document

## 1. Game overview

**Title:** Blockmancer Dungeon  
**Genre:** Falling-block combat roguelike puzzle RPG  
**Platforms:** Web first, Android through Capacitor, PC/Steam as future target  
**Session length:** 10–25 minutes per run  
**Target audience:** Puzzle players, roguelike players, casual strategy players, mobile-friendly arcade players

## 2. Core fantasy

The player is a Blockmancer: a mage who fights by controlling magical falling blocks inside a cursed dungeon. Every line clear is a spell strike. Every bad stack is battlefield danger. Every monster changes the board rules.

## 3. Core hook

> The player is not just stacking blocks. The player is fighting monsters by controlling a collapsing magical battlefield.

## 4. Unique selling points

1. Falling-block combat instead of score-only puzzle play.
2. Monsters actively disrupt the board.
3. Roguelike rewards create different builds each run.
4. Spellcasting uses mana generated by line clears.
5. Special block types create board-combat interaction.
6. Runs are short, readable, and replayable.

## 5. Design pillars

### Pillar 1 — Clear but tactical

The player should understand what happened after every move. Complexity should come from combinations, not hidden rules.

### Pillar 2 — Chaos with fairness

Enemy attacks and board hazards can create chaos, but the player must feel they had options.

### Pillar 3 — Build variety

Each run should encourage a different build: fire damage, frost control, bomb board-clear, combo healing, gold economy, or risky speed builds.

### Pillar 4 — Release-friendly scope

The release version should be polished and replayable without requiring massive art/content volume.

## 6. Core gameplay loop

```text
Choose hero
-> Enter map node
-> Fight / event / shop / rest / treasure
-> Clear lines to damage enemy and gain mana
-> Cast spells to survive or burst damage
-> Enemy attacks and disrupts board
-> Defeat enemy
-> Choose reward
-> Progress on map
-> Defeat boss or die
-> Unlock content / start new run
```

## 7. Run structure

A standard run has 10 stages:

| Stage | Typical node pressure            |
| ----: | -------------------------------- |
|     1 | Tutorial fight / low pressure    |
|     2 | Normal fight / event             |
|     3 | First elite option               |
|     4 | Shop/rest decision               |
|     5 | Mid-run difficulty spike         |
|     6 | More enemy disruption            |
|     7 | High-value treasure/elite choice |
|     8 | Pre-boss stabilization           |
|     9 | Final hard room                  |
|    10 | Boss: Falling King               |

## 8. Win and loss conditions

**Win:** Defeat the final boss, The Falling King.  
**Lose:** Player HP reaches 0 or the board tops out.

## 14. Tone and world

Dark fantasy arcade. The world is dangerous but playful. The dungeon should feel magical, unstable, and reactive.

## 15. Current risks

| Risk                                           | Impact | Mitigation                                                                  |
| ---------------------------------------------- | ------ | --------------------------------------------------------------------------- |
| Feels too close to classic falling-block games | High   | Different theme, block types, combat, enemy board effects, own terminology. |
| Board chaos feels unfair                       | High   | Predictable enemy intents, telegraphs, undo/reroll rewards, clear logs.     |
| Mobile controls feel bad                       | High   | Large buttons, hold-to-repeat, alternate swipe controls.                    |
| Balance too snowbally                          | Medium | Curves, caps, telemetry, hard/soft counters.                                |
| Content becomes hardcoded                      | High   | Use JSON content registry and validation.                                   |

## 16. V2 release direction — expanded stages and bosses

The MVP proves that the core loop is fun. The release version should become a larger roguelike run with clearer act structure, more boss variety, hero unlock goals, and stronger mobile portrait identity.

### Release run structure

The release run is divided into **5 acts**, each with its own enemy pool, visual theme, mechanics, mini-boss pressure, and final boss.

|   Act | Stage range | Theme             | Gameplay pressure                                 | Boss             |
| ----: | ----------- | ----------------- | ------------------------------------------------- | ---------------- |
| Act 1 | 1–6         | Cracked Dungeon   | Basic line-clear combat, low junk pressure        | Slime Baron      |
| Act 2 | 7–12        | Goblin Scrapworks | Junk blocks, board clutter, shop economy          | Junkmaster Gob   |
| Act 3 | 13–18       | Frost Crypt       | Freeze, slow, preview disruption, slippery blocks | Cryo Lich        |
| Act 4 | 19–24       | Gravity Ruins     | Heavy blocks, gravity shifts, speed spikes        | Stone Titan      |
| Act 5 | 25–30       | Royal Void Keep   | Curses, void blocks, boss phases, high speed      | The Falling King |

### Stage rules

```text
Normal fight: common enemy pool
Elite fight: stronger enemy + guaranteed high-tier reward
Event: risk/reward choice
Shop: spend gold, heal, remove curse, buy spell/relic
Rest: heal and stabilize fall speed
Treasure: reward without combat
Boss: act-ending fight with unique board rules
```

### Release boss target

Minimum release bosses:

```text
1. Slime Baron — tutorial boss / board flooding
2. Junkmaster Gob — junk pressure / economy disruption
3. Cryo Lich — freeze / next-block disruption
4. Stone Titan — armor / heavy blocks / locked columns
5. Mirror Witch — curses / spell cost manipulation / copy effects
6. The Falling King — final boss / speed, junk, shake, void collapse
```

Stretch bosses:

```text
7. Flame Hydra — multi-head burn pressure
8. Clockwork Maw — timer and lock-counter manipulation
9. Void Dragon — board deletion and unstable lines
```

## 18. Pixel-art / 32-bit visual identity

The release art direction is now:

> **32-bit inspired dark fantasy pixel art with arcade readability.**

Rules:

```text
- Use pixel-art sprites and pixel-perfect UI where possible.
- Do not use smooth vector UI as the final style.
- Use crisp outlines, limited palettes, and readable silhouettes.
- Use fantasy stone, rune, spell, and dungeon motifs.
- UI should feel like a 32-bit handheld/console RPG battle screen mixed with an arcade puzzle board.
```

Fonts:

```text
Primary UI font: pixel-art readable font
Numbers/damage font: chunky pixel display font
Body/help text: pixel font with high readability, not overly decorative
Fallback: system monospace only during development
```

## 19. Portrait-only mobile layout requirement

The game is designed primarily for **portrait mobile**. Landscape can remain unsupported or experimental.

Portrait screen vertical ratio:

```text
Top 1/5: battle screen, hero/enemy, HP bars, enemy intent, stage info
Middle 3/5: falling-block board, next block, hold block, inventory quick view
Bottom 1/5: mobile controls and spell buttons
```

The top battle area should feel like a compact **Suikoden-style RPG combat stage**: hero party/hero portrait on one side, enemy/boss on the other, damage numbers, spell effects, and readable HP/intent.

The board remains the main interactive area and must never be visually crowded by combat UI.

Detailed layout is defined in `21_PORTRAIT_MOBILE_UI_SPEC.md`.

## 20. Inventory, next block, and hold block visibility

During battle, the player must be able to see:

```text
- Next block queue
- Hold block
- Active spells
- Quick inventory/relic summary
- Current enemy intent
- Player HP/mana
```

Priority order:

```text
1. Active board readability
2. Mobile controls usability
3. Enemy intent and HP
4. Next block and hold block
5. Spells
6. Inventory/relics
7. Event log
```

Inventory should use compact icons in battle and full list/details outside battle.
