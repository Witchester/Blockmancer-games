# LiveOps and Post-Release Plan

## 1. Post-release philosophy

Ship a stable, fun game first. Use updates to expand, not to fix a broken foundation.

## 2. Patch cadence

Recommended:

```text
Launch week: hotfixes as needed
First month: weekly/biweekly small patches
After stability: monthly content/balance updates
```

## 3. Patch types

### Hotfix

```text
crashes
softlocks
save corruption
store-breaking bugs
major input issue
```

### Balance patch

```text
enemy tuning
spell costs
reward rarity
boss mechanics
shop prices
```

### Content update

```text
new hero
new boss
new spells
new relics
new events
new curses
new board blocks
```

## 5. Community feedback process

Track feedback categories:

```text
bugs
balance
controls
readability
performance
content suggestions
store/device issues
```

## 6. Versioning

Use semantic versioning:

```text
0.x alpha/beta
1.0 release
1.0.1 hotfix
1.1 content update
2.0 major expansion
```

## 7. Save compatibility

Before updates:

```text
[ ] Update save version
[ ] Add migration function
[ ] Test old save loading
[ ] Avoid deleting player unlocks
```
